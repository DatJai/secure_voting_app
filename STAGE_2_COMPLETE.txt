   ├─ Pre-Login Menu (3 pages):

   │  └─ 🔐 System Access (dual login)
   │
   ├─ Admin Menu (8 pages):
   │  ├─ 🏠 Home
   │  ├─ ✍️ Register Voter (admin-only)
   │  ├─ 🔑 Request Token
   │  ├─ 🗳️ Cast Vote
   │  ├─ 🔀 MixNet (admin-only)
   │  ├─ 📊 Tally (admin-only)
   │  ├─ 📜 Logs (admin-only)
   │  └─ 🚪 Logout
   │

      ├─ 🏠 Home
      ├─ 🔑 Request Token (voter-only)
      ├─ 🗳️ Cast Vote (voter-only)
      └─ 🚪 Logout

✅ PAGE-LEVEL SECURITY
   ├─ Every protected page checks: authenticated + user_type
   ├─ Access denied → Warning message + Return
   ├─ Voter data pre-filled from session (cannot be edited)
   ├─ Voter ID used from session in all API calls
   └─ No way to spoof voter identity

✅ SESSION STATE MANAGEMENT
   ├─ authenticated: bool (True/False)
   ├─ user_type: "admin" or "voter"
   ├─ admin_token: JWT token (admin only)
   ├─ voter_id: VOTER-001 format (voter only)
   ├─ voter_name: Display name (voter only)
   └─ All cleared on logout

✅ AUTO-GENERATED VOTER IDs
   ├─ Format: VOTER-001, VOTER-002, etc.
   ├─ Generated at backend during registration
   ├─ Unique per voter
   ├─ Used for token tracking and voting
   └─ Not user-input (prevents ID collisions)

SECURITY IMPLEMENTATION DETAILS

═════════════════════════════════════════════════════════════════════════════

✅ PAGE-LEVEL AUTHORIZATION PATTERN

Every protected page follows this security check:

```python
def page_xxx():
    # ✅ SECURITY CHECK (ALWAYS FIRST!)
    if not st.session_state.authenticated or st.session_state.user_type != "REQUIRED_ROLE":
        st.warning("⚠️ {Role} login required.")
        return  # Exit - do not show page content
    
    # Safe to proceed - user is authenticated and authorized
    st.title("Page Title")
    # ... page implementation
```

✅ VOTER DATA SECURITY

Voter ID & Name CANNOT be spoofed:
  ├─ Stored in session_state (server-side in browser memory)
  ├─ Pre-filled in forms (read-only display)
  ├─ Used in all API calls (from session, not user input)
  ├─ Cleared on logout
  └─ Backend validates ownership on every request

✅ ADMIN SECURITY

Admin token:
  ├─ JWT token with 2-minute expiry
  ├─ Used for admin_client API calls
  ├─ Stored in session_state
  ├─ Automatically handled by base_client
  └─ Cleared on logout

✅ FRONTEND vs BACKEND SECURITY

Frontend (This Implementation):
  ├─ ✅ User interface enforcement
  ├─ ✅ Navigation menu filtering
  ├─ ✅ Page-level access checks
  ├─ ✅ Session state management
  ├─ ✅ Clear warning messages
  └─ ⚠️ Can be bypassed (browser dev tools)

Backend (Must Implement):
  ├─ ✅ JWT validation on all requests
  ├─ ✅ Voter ID ownership verification
  ├─ ✅ Admin-only endpoint protection
  ├─ ✅ Vote anonymization
  ├─ ✅ Audit logging
  ├─ ✅ Input validation
  └─ ⚠️ CRITICAL FOR PRODUCTION

WORKFLOWS: HOW IT WORKS

═════════════════════════════════════════════════════════════════════════════

ADMIN WORKFLOW:
───────────────

1. START
   └─ Open http://localhost:8501
   └─ See: Home, Register, System Access

2. LOGIN (Admin)
   └─ Click: 🔐 System Access
   └─ Tab: 👨‍💼 Admin Login
   └─ Enter: admin / adminpass
   └─ Session: authenticated=True, user_type="admin"
   └─ Menu: Shows 8 admin pages

3. REGISTER VOTERS
   └─ Click: ✍️ Register Voter
   └─ Form: Enter voter name + email
   └─ Backend: Auto-generates VOTER-001
   └─ Display: List all voters in table

4. REQUEST TOKENS
   └─ Click: 🔑 Request Token
   └─ [Admin version: Can select voters]
   └─ Select: VOTER-001
   └─ Action: Issue blind token
   └─ Result: Token issued, shown in JSON

5. CAST VOTE (Demo)
   └─ Click: 🗳️ Cast Vote
   └─ [Admin can test voting]
   └─ Select: Candidate
   └─ Submit: Record test vote

6. ANONYMIZE
   └─ Click: 🔀 MixNet
   └─ Set: Mixing layers (e.g., 5)
   └─ Click: Run MixNet
   └─ Action: Shuffle & anonymize all ballots
   └─ ⚠️ Point of no return!

7. VIEW RESULTS
   └─ Click: 📊 Tally
   └─ Display: Vote counts, percentages
   └─ Export: Download CSV of results
   └─ Purpose: Complete election results

8. AUDIT TRAIL
   └─ Click: 📜 Logs
   └─ Display: All system events
   └─ Content: Timestamp, Type, Message
   └─ Purpose: Complete activity log

9. LOGOUT
   └─ Click: 🚪 Logout
   └─ Action: Clear all session data
   └─ Result: Return to pre-login menu

VOTER WORKFLOW:
───────────────

1. START
   └─ Open http://localhost:8501
   └─ See: Home, Register, System Access

2. REGISTER (Optional - self-service)
   └─ Click: 📝 Register
   └─ Form: Enter name + email
   └─ Backend: Generates VOTER-002
   └─ Display: Shows your Voter ID
   └─ Note: Will use this ID to login

3. LOGIN (Voter)
   └─ Click: 🔐 System Access
   └─ Tab: 🗳️ Voter Login
   └─ Enter: VOTER-002 / Jane Doe
   └─ Backend: Verifies voter exists
   └─ Session: authenticated=True, user_type="voter"
   └─ Menu: Shows 4 voter pages

4. REQUEST TOKEN
   └─ Click: 🔑 Request Token
   └─ Display: Jane Doe (ID: VOTER-002)
   └─ [Cannot change - from session]
   └─ Action: Request Blind Token
   └─ Result: Token issued to this voter

5. CAST VOTE
   └─ Click: 🗳️ Cast Vote
   └─ Display: Jane Doe (ID: VOTER-002)
   └─ [Cannot change - from session]
   └─ Select: Your candidate
   └─ Submit: Cast Vote
   └─ Result: Ballot receipt (confirmation)

6. LOGOUT
   └─ Click: 🚪 Logout
   └─ Action: Clear session data
   └─ Result: Return to pre-login menu
