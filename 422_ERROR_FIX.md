# 422 Unprocessable Entity - Root Cause & Complete Fix

## 🎯 Summary

The **422 Unprocessable Entity** error occurred because the frontend and backend had **incompatible data schemas** for voter registration.

---

## ❌ Root Cause

### The Mismatch

**Frontend was sending:**
```json
POST /voters/register
{
  "name": "John Doe",
  "email": "john@example.com"
}
```

**Backend was expecting:**
```json
POST /voters/register
{
  "voter_id": "VOTER-001",
  "name": "John Doe"
}
```

### Why 422?

FastAPI's Pydantic validator rejected the request because:
- ❌ `VoterCreate` model required `voter_id` field (not in request)
- ❌ `VoterCreate` model didn't accept `email` field (extra field in request)
- ❌ **Validation failed** → 422 Unprocessable Entity

---

## ✅ Complete Fix (4 Components)

### 1. Fixed Pydantic Model: `api/models/voter.py`

**Problem:** Model expected `voter_id` instead of `email`

**Solution:**
```python
class VoterCreate(BaseModel):
    name: str      # ✅ Required
    email: str     # ✅ Required
    # voter_id is generated by backend, not provided by client
```

**Change:**
- ❌ Before: `VoterCreate(voter_id: str, name: str)`
- ✅ After: `VoterCreate(name: str, email: str)`

---

### 2. Fixed Registration Endpoint: `api/routes/voters.py`

**Problem:** Endpoint expected `voter_id` from frontend instead of auto-generating it

**Solution:**
```python
@router.post("/register", response_model=ResponseModel)
def register_voter(v: VoterCreate):
    repo = VoterRepository()
    try:
        # ✅ AUTO-GENERATE voter_id
        last_voter = repo.get_last_voter()
        if last_voter:
            last_id = last_voter.get("voter_id", "VOTER-000")
            try:
                last_num = int(last_id.split("-")[1])
            except (IndexError, ValueError):
                last_num = 0
        else:
            last_num = 0
        
        new_voter_id = f"VOTER-{last_num + 1:03d}"  # VOTER-001, VOTER-002, etc.
        
        # ✅ PASS EMAIL to repository
        repo.add_voter(new_voter_id, v.name, v.email)
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))

    try:
        authority = VotingAuthority(get_conn())
        authority.register_voter(new_voter_id)
    except Exception:
        pass

    # ✅ RETURN generated voter_id
    return ResponseModel(
        message="voter registered", 
        data={"id": new_voter_id, "name": v.name}
    )
```

**Changes:**
- ✅ Now accepts `name` and `email` (not `voter_id`)
- ✅ Auto-generates `voter_id` by getting last voter and incrementing
- ✅ Passes `email` to repository
- ✅ Returns generated `voter_id` to client

### 3. Updated Repository: `db/repositories/voter_repository.py`

**Problem:** Repository didn't accept `email` parameter or provide `get_last_voter()`

**Solution:**
```python
class VoterRepository:
    def add_voter(self, voter_id: str, name: str, email: str = None):
        """Add a new voter with optional email"""
        conn = get_conn()
        with conn.cursor() as cur:
            cur.execute("""
                INSERT INTO voters(voter_id, name, email, has_token, has_voted)
                VALUES (%s, %s, %s, false, false)
                ON CONFLICT (voter_id) DO NOTHING
            """, (voter_id, name, email))  # ✅ Pass email
        conn.commit()
        conn.close()

    def get_last_voter(self):
        """Get the last registered voter for ID generation"""
        conn = get_conn()
        with conn.cursor() as cur:
            cur.execute("SELECT * FROM voters ORDER BY voter_id DESC LIMIT 1")
            result = cur.fetchone()
        conn.close()
        return result

    # ... rest of repository methods ...
```

**Changes:**
- ✅ `add_voter()` now accepts `email` parameter
- ✅ New method `get_last_voter()` returns last registered voter
- ✅ Database query stores email in voters table

---

### 4. Updated Database Schema: `.devcontainer/init-db.sql`

**Problem:** Database schema didn't have `email` column

**Solution:**
```sql
CREATE TABLE IF NOT EXISTS voters (
    voter_id TEXT PRIMARY KEY,
    name TEXT,
    email TEXT,                          -- ✅ Added email column
    has_token BOOLEAN DEFAULT FALSE,
    has_voted BOOLEAN DEFAULT FALSE
);
```

**Change:**
- ✅ Added `email TEXT` column to voters table

## 🔍 How to Identify Similar Issues

### Signs of 422 Errors
- ❌ Request body doesn't match Pydantic model
- ❌ Missing required fields
- ❌ Extra unexpected fields
- ❌ Wrong data types (e.g., string where int expected)

### How to Debug
1. Check Pydantic model definition
2. Compare with actual request from frontend
3. Verify data types match
4. Check for typos in field names

### Solution Pattern
1. Fix Pydantic model to match frontend
2. Update endpoint business logic
3. Update database schema if needed
4. Test with sample requests
